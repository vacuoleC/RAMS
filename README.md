## 1. 这个项目是什么

> 🗣️ **大白话**
> 水库里会长藻，藻长太多会变成"藻华"——水面绿油油一片，影响水质甚至供水安全。我们要做一个聪明的电脑程序，让它学会看历史监测数据，**提前预测**藻什么时候会变多、在哪个水深最多、什么时候要拉警报。
> 这个程序**不追求"小"**，追求的是**预测得最准、结果真实可信**。它背后是一个约 3 万多个可调"旋钮"（参数）的神经网络，配上有大算力的服务器，跑出来的结果已经在真实数据上超过了所有对比的基线方法。

**项目目标**：追求**最大预测精度 + 真实科研结果**，用一个深度学习系统（RAMS-Net）监测水库藻类，服务五个研究问题。监测对象是**单个水库（站点已匿名）**，数据跨度 **2021–2025**。

### 核心架构：一个共用大脑 + 五个专项小助手

> 🗣️ **大白话**
> 你可以把它想成"一个共用的大脑 + 五个专项小助手"。所有数据先交给**大脑**（我们叫它 Backbone，用的是一种叫 GRU 的网络，擅长记"昨天、前天发生了什么"），大脑理解"现在水库是什么状况"，整理成一份它自己看得懂的笔记；然后把笔记分给五个**小助手**，每个助手专做一件事。
> 关键点：五个小助手都**只看大脑整理的笔记，谁都不直接碰原始数据**。这样既省力，五件事还能共享大脑学到的东西——这是整个项目设计的灵魂。

技术上：数据先进入一个**共享 GRU Backbone（RAMS-Net，实际约 3.2 万参数，GRU hidden=64）**，输出统一的时空表征，再分发给五个任务头。**这不是五个各自为政的模型。**

五个任务头分别负责：

| 编号 | 这个助手做什么 | 大白话 |
|---|---|---|
| **M1** | 藻类浓度预测（回归） | 预测未来 7 天各水深藻浓度会涨还是会跌、涨多少（输出 9 个分位数，自带"可能的范围"） |
| **M2** | 热分层识别（分类） | 判断水体上下温度是否分层（夏天常见，影响藻的分布） |
| **M3** | 监测点位优化 | 在 20 个水深里，挑出最该装传感器的几个深度（GAT + 贪心算法） |
| **M4** | 藻华预警（分级） | 给出"安全 / 注意 / 警告 / 危险"之类的预警等级，还能报出预警概率 |
| **M5** | 机理与时滞分析 | 分析"刮风下雨之后，过多久藻会变多"这种因果关系 |

> 📎 其中 M3 用了图网络（GAT）+ 贪心选点，M5 用的是 PCMCI+ 因果分析方法，**不需要训练**，直接算。五个头都已有真实数据的探索实证。

### 训练方式：两阶段（先练准，再练全）

1. **第一阶段**：单独训练 M1（浓度预测），把大脑练到"点预测最准"；
2. **第二阶段**：**冻结大脑**（不让它再变），只微调五个小助手，让 M2/M4 也能输出（正式配置 20+10 轮）。

这样既保住了预测精度，又让预警和分层判断可用，是多个实验对比选出来的最优方案。

### 数据长什么样

> 🗣️ **大白话**
> 喂给大脑的数据，可以想象成一摞"体检表"：每张表记录某个时刻、从水面到 10 米深、一共 20 个水深层的各项指标（水温、藻浓度、风速等）。程序把"最近 30 天"的数据打包成一份笔记喂给大脑，让它预测**未来 7 天**的走势。

- 原始数据：**20 个水深（0.5m–10.0m）**，每个时刻每层 23 个指标（13 个水质 + 6 个气象 = 19 个实测，再加 4 个用物理公式推算补齐的）。
- 生产管线（0.2.0）：先按天聚合，再按"最近 30 天（T=30）→ 未来 7 天（H=7）"切成训练样本；预测目标是**增量 Δ**（未来浓度 − 当前浓度），评估时再还原成真实浓度。

## 3. 角色分工：你、AI、子代理、机器

> 🗣️ **大白话**
> 分工是这样的——**Claude Code 负责写代码**，并做"冒烟测试"（像新买的电器先通电两秒、看冒不冒烟，而不是马上拿来用一整天）。大一点的模块任务会让**专门的子代理**去执行，主会话把关。只要代码"点着了、不冒烟"，就**停下来交给你**。
> 真正费时间的**正式训练**（让程序反复看几十万条数据学规律，在 H100 上跑）由**你来跑或安排**。这样 AI 不会偷偷烧掉你的机时，也不会在长任务里跑飞失控。

这是整个项目**最重要的一条边界**，请务必记住：

- **AI（Claude Code + 子代理）做**：写代码、改代码、跑各种快速检查、跑**冒烟测试**（用很少的数据跑 1–2 个批次，验证"不报错、数值正常、输出形状对"）、跑小规模探索实验。做完就停，明确说一句"**冒烟通过，可以开始正式训练**"。
- **你（人类）做**：看 AI 的汇报、确认没问题、评审每个模块的产出、然后**亲自执行/安排正式的算力机训练**。训练在哪台机器上跑见第 4 节。

**冒烟测试通过的判据**（满足这三条 AI 就该停手）：① 程序不崩溃、不报错；② 损失值（loss，衡量模型当前好坏的数字）是正常有限的数，不是 NaN（坏掉的数）或无穷大；③ 输出的数据形状和预期一致。

**子代理是怎么用的**：0.2.0 的五个落地模块，每个都按"控制器技能"的流程执行——冻结设计里定好目标和验收 → 子代理实现 + 冒烟 → 交回主会话评审 → 通过才继续。钩子会记录每次工具调用，状态机全程可审计。

## 5. 数据是怎么处理和保存的

> 🗣️ **大白话**
> 我们手上有几个 Excel 文件，记录了这个水库 2021–2025 的监测数据，但它们**格式乱、分散在很多张表里、还有缺失**，直接用很麻烦。
> 所以第一件大事是"**洗数据**"：把它们合并、对齐、补缺、统一格式，洗成一份干净规整的"**标准档案**"。这个洗的动作**只做一次**。之后所有人、所有程序都**只认这份标准档案，再也不碰原始 Excel**——这样保证大家用的数据完全一致，不会各洗各的、洗出不同结果。

### 我们手上的原始数据（实测情况，站点已匿名）

| 内容 | 结构 | 规模 | 时间跨度 |
|---|---|---|---|
| 藻类观测（20 个深度分表，0.5m→10.0m） | 20 张 sheet，列名一致 | **258,542** 条 | 2021–2025 |
| 气象观测 | 一张表有数据，其余 sheet 为空（忽略） | **232,067** 条 | 2021–2025 |
| 0.5m 层合并样例 | 仅最浅层的合并样例（当校验参考用） | 约 12,800 | 同上 |

> 📎 气象数据每 **10 分钟**采一次，藻类约每 **3 小时**采一次。原始表里**时间是文本格式**，读进来要专门转换成日期。

### 三层存储：从乱到净，层层收敛

> 🗣️ **大白话**
> 数据分三个"抽屉"放：
> - **原始抽屉**：放最原始的 Excel，**只读不动、永不修改**（这是底线，原始证据不能破坏）；
> - **中间抽屉**：放洗到一半的半成品，丢了也能重新生成；
> - **标准抽屉**：放洗好的那份标准档案——这是**唯一**给模型用的数据，必须保留好。

```
data/
├── raw/         # 原始 Excel，只读、永不修改、永不上传
├── interim/     # 洗到一半的中间产物，可随时重新生成
└── processed/   # 标准数据集 standard.parquet（模型唯一数据源）+ 归一化参数
```

### 几个关键处理决定

> 🗣️ **大白话**
> 下面这几条是洗数据时定下的规矩，普通同学了解个大意即可：把分散的 20 张表叠成一张长表、把 Excel 换成又小又快的格式、把中文列名换成英文（避免程序出乱码）、缺的几个指标用物理公式估算补上。

1. **20 张深度表叠成一张"长表"**：保留一个 `depth`（深度）列来区分，而不是摊成 20 组列。
2. **Excel → Parquet 格式**：原始 Excel 读得慢、时间还是文本；换成 Parquet（带压缩）后，整份数据只有约 **26MB**，机器内存就能一次全部装下，**不用分块**。
3. **中文列名 → 英文**（如 蓝藻浓度 → `cyano_conc`）：避免代码、编码、模型导出时的中文乱码问题；中英对照表记在配置里。
4. **补齐 4 个缺失指标**：溶解氧、pH、悬浮物、太阳辐射，用物理公式从已有数据推算，并明确标注它们是"推算来的"（`source: augmented`），不冒充实测。这样指标从 19 个补到 23 个。
5. **归一化参数单独存、且只用训练数据来算**：避免"用到了未来数据"这种作弊，保证评估结果可信。

> 📎 13 个水质指标 + 6 个气象指标 = **19 个实测指标**，再加 4 个推算指标 = **23 个**。`站点 / 时间 / 深度` 这三个是"坐标"，不算指标。

### 🔒 数据保密（每个人都要遵守）

> 🗣️ **大白话**
> 这批数据是**涉密**的。规矩很硬：**不准把真实数值打印到屏幕、写进日记、传到任何网盘或云端**。需要展示时，只展示"形状、列名、平均值"这类统计信息，不展示具体某一条记录。代码版本管理也只在本地做，不往网上传。

- 所有含真实数值的文件（Excel、标准数据集、中间产物）都进 `.gitignore`，**永不提交、永不上传**（数据文件夹用根锚定规则保护，不影响 `rams/` 源码入库）。
- 任何输出只给形状、列名、统计量（均值/分位数），**不给原始数据行**。
- 禁用一切外发服务（如 W&B 等云端实验平台），实验记录只用**本地** MLflow。
- 学术诚信：不伪造数据或结果；推算字段如实标注来源。

## 6. 关键成果（0.2.0 落地完成）

> 🗣️ **大白话**
> 这一节是"成绩单"。简单说：**这个模型学得比"一直不变"强得多**，能提前两个星期预报藻华警报，而且报出来的"可能范围"是准的。这些数字都是在真实数据、严格评估协议下跑出来的，不是碰运气。

## 9. 名词小词典（给没有计算机背景的同学）

> 🗣️ **大白话**
> 下面是文档里会反复出现的词，用最日常的话解释一遍。看到不懂的词就回来查。

| 名词 | 大白话解释 |
|---|---|
| **GPU / 显卡** | 电脑里专门做"大量并行计算"的部件，训练 AI 模型主要靠它，比普通 CPU 快很多。 |
| **显存** | 显卡自己的内存。本地这张 4060 只有 8G，比较小；算力机的 H100 有 80G，大得多。 |
| **conda 环境** | 给一个项目单独隔出来的"软件工具箱"，避免不同项目的工具版本互相打架。 |
| **训练 vs 推理** | **训练** = 让模型看大量历史数据、自己总结规律（慢、费机时）；**推理** = 拿学好的模型去预测新情况（快）。 |
| **参数（旋钮）** | 模型内部可调整的"旋钮"数量，越多越复杂。我们的 RAMS-Net 约 **3.2 万个**。 |
| **GRU** | 一种擅长"记过去"的神经网络，记得住"前几天发生了什么"，适合预测时间序列。 |
| **batch（批大小）** | 模型一次同时看多少条数据。显存小就只能调小。 |
| **epoch（轮次）** | 把全部训练数据完整过一遍叫一个 epoch，通常要过几十遍。 |
| **冒烟测试** | 用很少的数据快速跑一两下，只验证"代码不报错、能跑通"，**不追求结果好坏**。像新电器先通电两秒看冒不冒烟。 |
| **CRPS** | 衡量"预测得有多准"的指标，越低越好，还同时惩罚"报错的范围"（既怕报偏，也怕报得没底气）。 |
| **持久化基线** | 最笨但最难缠的对手："直接假设明天和今天一样"。模型必须明显超过它才算真有本事。 |
| **覆盖率** | 模型报的"可能范围"里，真实值真的落在里面的比例。目标 80%，现在是 76.6%。 |
| **分位数（quantile）** | 把"可能的范围"切成几档（比如 5%、50%、95%），模型输出的不是一个数，而是一条"可能性曲线"。 |
| **增量 Δ（delta）** | 我们不直接猜"明天是多少"，而是猜"明天比今天**变了多少**"，再把今天加上去。实证发现这样更准。 |
| **藻华预警 / 召回 / 提前量** | 预警 = 提前说"要爆发了"；召回 = 该拉警报的藻华事件里拉响了几次；提前量 = 警报比爆发早多少天。 |
| **张量（tensor）** | 多维的"数字表格"，是模型处理数据的基本形式。 |
| **loss（损失）** | 一个数字，衡量模型当前预测得有多差。训练就是想办法让它越来越小。 |
| **Parquet** | 一种又小又快的数据文件格式，比 Excel 高效得多。 |
| **Git** | 给代码做"存档和版本管理"的工具，可随时回到之前的版本。我们**只在本地用，不往网上传**。 |
| **Hydra** | 管理"配置"的工具，改参数（换显卡、改批大小）时只改配置、不动代码。 |
| **MLflow** | 记录每次实验"用了什么设置、结果如何"的工具，方便对比。我们**只在本地用**。 |
| **ONNX** | 一种通用的"模型打包格式"，方便把训练好的模型搬到不同电脑上跑。 |
| **Backbone（主干）** | 前面说的"共用大脑"，负责把原始数据加工成统一的表征（我们用的是 GRU）。 |
| **任务头（head）** | 接在主干后面的"专项小助手"，各做一种预测。 |
| **Claude Code** | 我们用的 AI 编程助手，你用中文给它派活、它帮你写改代码、跑冒烟测试；大模块由它派专门的**子代理**执行。 |
| **子代理** | 大任务里被派出去专门干某一块的小 AI 工作单元，干完把结果交回主会话。 |
| **治理框架 / 控制器** | 一套"流程和规矩的机器"（build-supervised-project 生成），规定任务怎么冻结、怎么推进、怎么评审、怎么验收。 |
| **归一化** | 把不同量纲的指标（比如温度和浓度）缩放到差不多的范围，方便模型学习。 |

## 10. 常见问题（FAQ）

> 🗣️ **大白话**
> 下面是大概率会遇到的问题和应对办法。遇到拿不准的，把屏幕上的报错信息原样发给负责人即可——**报错信息是最有价值的排查线索**。

**Q：装环境时装一半报错了怎么办？**
A：用 `environment.yml` 一次建好；卡在哪一步就把那一步的报错发出来排查，不要跳过报错继续往下装。

**Q：验证 GPU 那条命令输出了 `False`？**
A：说明 torch 没装成 GPU 版，或显卡驱动 / CUDA 版本不匹配。**先别继续**，把完整输出发给负责人。

**Q：图表里的中文变成了一个个方框？**
A：正常现象——本机缺中文字体。所以我们规定**图表标注一律用英文**，按规矩来即可。

**Q：跑训练时报 `CUDA out of memory`（显存不够）？**
A：**先调小批大小**或序列长度，不要一上来就怀疑代码。本地 8G 显存比较小，这很常见；大规模训练上 H100。

**Q：担心 AI 把后面的步骤一口气都做完、跑飞了？**
A：规矩里写了它每个模块/阶段做完**必须停下等你确认**。万一它没停，直接打断并提醒它"按 FLOW 一次只做一个任务"。

**Q：数据能传到网盘 / 云端备份吗？**
A：**不能。** 数据涉密，规矩里禁止任何外发；备份也只能用本地或离线介质。本地与算力机之间只能用 `sync_sensecore.py` 走内网同步。

**Q：我不懂代码，能看懂 AI 的汇报吗？**
A：它的汇报是中文三段式，你**重点看"冒烟是否通过"和"下一步建议"两项**就够了，其余可以略读。

**Q：本地 4060 能跑正式训练吗？**
A：本地主要用来**写代码 + 冒烟测试**。正式的 0.2.0 训练在 **sensecore H100** 上跑（3 种子 × 17 滚动窗口），可以扩容到 8×H100。换机器只改一个硬件配置选项，代码不动。

**Q：0.2.0 说"落地完成"，模型已经能用了？**
A：核心成果（预测、预警、对比基线、测试打包）都已落地并验收。**部署成线上服务**（ONNX + FastAPI）是下一步，还没做；论文草稿已就绪。
