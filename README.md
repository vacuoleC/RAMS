## 1. 这个项目是什么

> 🗣️ **大白话**
> 水库里会长藻，藻长太多会变成"藻华"——水面绿油油一片，影响水质甚至供水安全。我们要做一个聪明的电脑程序，让它学会看历史监测数据，**提前预测**藻什么时候会变多、在哪个水深最多、什么时候要拉警报。
> 这个程序故意做得很"小"（内部不到两百万个可调"旋钮"，相当于一个很轻巧的大脑），所以将来能装进水库现场那种不太强的电脑里日常使用，而不是非得用昂贵的大服务器。

**项目目标**：用一个轻量深度学习系统监测水库藻类，服务五个研究问题。监测对象是单个站点（编号 0902，已脱敏），数据跨度 2021-03 至 2025-09，约四年半。

### 核心架构：一个共用大脑 + 五个专项小助手

> 🗣️ **大白话**
> 你可以把它想成"一个共用的大脑 + 五个专项小助手"。所有数据先交给**大脑**（我们叫它 Backbone），大脑负责理解"现在水库是什么状况"，整理成一份它自己看得懂的笔记；然后把这份笔记分给五个**小助手**，每个助手专做一件事。
> 关键点：五个小助手都**只看大脑整理的笔记，谁都不直接碰原始数据**。这样既省力，五件事还能共享大脑学到的东西——这是整个项目设计的灵魂。

技术上：数据先进入一个**共享 Backbone（RAMS-Net，约 1.9M 参数）**，输出统一的时空表征，再分发给五个任务头。**这不是五个各自为政的模型**。

五个任务头分别负责：

| 编号 | 这个助手做什么 | 大白话 |
|---|---|---|
| **M1** | 藻类浓度预测（回归） | 预测未来一段时间各水深的藻有多少 |
| **M2** | 热分层识别（分类） | 判断水体上下温度是否分层（夏天常见，影响藻的分布） |
| **M3** | 监测点位优化 | 在 20 个水深里，挑出最该装传感器的几个深度 |
| **M4** | 藻华预警（分级） | 给出"安全 / 注意 / 警告 / 危险"之类的预警等级 |
| **M5** | 机理与时滞分析 | 分析"刮风下雨之后，过多久藻会变多"这种因果关系 |

> 📎 其中 M5 用的是一种叫 PCMCI+ 的因果分析方法，**不需要训练**，直接算。

### 数据长什么样

> 🗣️ **大白话**
> 喂给大脑的数据，可以想象成一摞"体检表"：每张表记录某个时刻、从水面到 10 米深、一共 20 个水深层的各项指标（水温、藻浓度、风速等）。模型一次看连续的 96 个时刻。

输入张量形状为 `(B, T=96, D=20, C=19)`，补齐 4 个推算字段后通道数变成 `C=23`。其中 `T=96` 是时间步，`D=20` 是 0.5m–10.0m 共 20 个深度层，`C` 是每个点的指标个数。

## 2. 这套文件是怎么组织的

> 🗣️ **大白话**
> 这个项目有一个 AI 编程助手（叫 **Cline**）帮我们写代码。为了让它**按规矩干活、不乱来**，我们给它准备了几份文件：

> - 两份是**"活页本"**——一份是施工进度表，一份是施工日记，它边干边更新。
> 你现在看的这份 README 是**给人看的总说明**，AI 不读它（免得占用它的"记忆"）。

项目根目录是 `D:\coding\26AIendwork\`。规则体系由四份文件构成，外加这份 README：

|---|---|---|---|---|

| `README.md` | 项目根 | **总说明**（就是本文件） | 给人看 | 人读 |

#### 项目根还有哪些"工程文件"（全部在 .gitignore 保护下不进版本控制）

| `scripts/` | CLI 入口（`build_dataset` / `train` / `eval` / `predict` / `export` / `serve`） |

## 3. 角色分工：你、AI 助手、机器

> 🗣️ **大白话**
> 分工是这样的——**AI 助手负责写代码**，并做一个叫"冒烟测试"的快速试运行（就像新买的电器先通电两秒、看冒不冒烟，而不是马上拿来用一整天）。只要它确认代码"点着了、不冒烟"，就**停下来交给你**。
> 真正费时间的**训练**（让程序反复看几十万条数据学规律，可能跑几个小时）由**你自己来跑**。这样 AI 不会偷偷烧掉你的机时，也不会在长任务里跑飞失控。

这是整个项目**最重要的一条边界**，请务必记住：

- **AI 助手（Cline）做**：写代码、改代码、跑各种快速检查、跑**冒烟测试**（用很少的数据跑 1–2 个批次，验证"不报错、数值正常、输出形状对"）。做完就停，明确说一句"**冒烟通过，可以开始正式训练**"。
- **你（人类）做**：看 AI 的汇报、确认没问题、然后**亲自执行真正的训练命令**。训练在哪台机器上跑见第 4 节。

**冒烟测试通过的判据**（满足这三条 AI 就该停手）：① 程序不崩溃、不报错；② 损失值（loss，衡量模型当前好坏的数字）是正常有限的数，不是 NaN（坏掉的数）或无穷大；③ 输出的数据形状和预期一致。

> 🗣️ **大白话**

## 5. 数据是怎么处理和保存的

> 🗣️ **大白话**
> 我们手上有三个 Excel 文件，记录了水库这几年的监测数据，但它们**格式乱、分散在很多张表里、还有缺失**，直接用很麻烦。
> 所以第一件大事是"**洗数据**"：把它们合并、对齐、补缺、统一格式，洗成一份干净规整的"**标准档案**"。这个洗的动作**只做一次**。之后所有人、所有程序都**只认这份标准档案，再也不碰原始 Excel**——这样保证大家用的数据完全一致，不会各洗各的、洗出不同结果。

### 我们手上的原始数据（实测情况）

| 文件 | 结构 | 行数 | 时间跨度 |
|---|---|---|---|
| 藻类检测数据_分深度整理.xlsx | 20 个 sheet（0.5m→10.0m，列名一致） | 258,542 | 2021-03 → 2025-09 |
| 气象数据.xlsx | `Sheet1` 有数据，`Sheet2/3` 是空的（忽略） | 232,067 | 同上 |
| 藻类_气象_最近时刻匹配.xlsx | 仅 0.5m 层的合并样例（当校验参考用） | 12,800 | 同上 |

> 📎 气象数据每 **10 分钟**采一次，藻类约每 **3 小时**采一次。原始表里**时间是文本格式**，读进来要专门转换成日期。

### 三层存储：从乱到净，层层收敛

> 🗣️ **大白话**
> 数据分三个"抽屉"放：
> - **原始抽屉**：放最原始的 Excel，**只读不动、永不修改**（这是底线，原始证据不能破坏）；
> - **中间抽屉**：放洗到一半的半成品，丢了也能重新生成；
> - **标准抽屉**：放洗好的那份标准档案——这是**唯一**给模型用的数据，必须保留好。

```
data/
├── raw/         # 原始 Excel，只读、永不修改、永不上传
├── interim/     # 洗到一半的中间产物，可随时重新生成
└── processed/   # 标准数据集 standard.parquet（模型唯一数据源）+ 归一化参数
```

### 几个关键处理决定

> 🗣️ **大白话**
> 下面这几条是洗数据时定下的规矩，普通同学了解个大意即可：把分散的 20 张表叠成一张长表、把 Excel 换成又小又快的格式、把中文列名换成英文（避免程序出乱码）、缺的几个指标用物理公式估算补上。

1. **20 张深度表叠成一张"长表"**：保留一个 `depth`（深度）列来区分，而不是摊成 20 组列。
2. **Excel → Parquet 格式**：原始 Excel 读得慢、时间还是文本；换成 Parquet（带压缩）后，整份数据只有约 **26MB**，本地机器内存就能一次全部装下，**不用分块**。
3. **中文列名 → 英文**（如 `蓝藻浓度 → cyano_conc`）：避免代码、编码、模型导出时的中文乱码问题；中英对照表记在配置里。
4. **补齐 4 个缺失指标**：溶解氧、pH、悬浮物、太阳辐射，用物理公式从已有数据推算，并明确标注它们是"推算来的"（`source: augmented`），不冒充实测。这样指标从 19 个补到 23 个，和模型需要的 `C=23` 对上。
5. **归一化参数单独存、且只用训练数据来算**：避免"用到了未来数据"这种作弊，保证评估结果可信。

> 📎 13 个水质指标 + 6 个气象指标 = **19 个实测指标**，再加 4 个推算指标 = **23 个**。`站点 / 时间 / 深度` 这三个是"坐标"，不算指标。

### 🔒 数据保密（每个人都要遵守）

> 🗣️ **大白话**
> 这批数据是**涉密**的。规矩很硬：**不准把真实数值打印到屏幕、写进日记、传到任何网盘或云端**。需要展示时，只展示"形状、列名、平均值"这类统计信息，不展示具体某一条记录。代码版本管理也只在本地做，不往网上传。

- 所有含真实数值的文件（Excel、标准数据集、中间产物）都进 `.gitignore`，**永不提交、永不上传**。
- 任何输出只给形状、列名、统计量（均值/分位数），**不给原始数据行**。
- 禁用一切外发服务（如 W&B 等云端实验平台），实验记录只用**本地** MLflow。
- 学术诚信：不伪造数据或结果；推算字段如实标注来源。

## 6. 整个项目分七步走（七个阶段）

> 🗣️ **大白话**

## 7. 怎么给 AI 助手派活

> 🗣️ **大白话**
> 你**不需要懂代码**也能指挥这个 AI。做法很简单：用中文给它一个明确的**小任务**（比如"做第 0.1 步"），它做完会用固定格式向你汇报三件事——**做了什么、跑出来什么结果、建议下一步做什么**。你看完觉得 OK，再让它做下一个。它不会自作主张把后面的步骤一口气都做了。

### 派活的节奏

1. **你**：用中文派一个具体任务（一次只派一个）。
2. **AI**：先读 `FLOW.md`（确认现在该做哪步）和 `LOG.md`（看已有产物、避免重复踩坑）→ 写代码 → 自检 → 跑冒烟测试 → 更新 `FLOW.md`（进度推进）和 `LOG.md`（追加一条记录）→ 用**三段式**向你汇报。
3. **你**：看汇报，重点看「**冒烟是否通过**」和「**下一步建议**」两项。确认无误，再派下一个任务。

### 开工第一句（可直接复制粘贴给 AI）

> 读 `.clinerules`（含 00、01），再读 `FLOW.md` 和 `LOG.md`。按 FLOW 的**任务 0.1** 初始化项目骨架，完成后更新 FLOW 状态、给 LOG 追加记录，并按三段式汇报。**先别做 0.2。**

### AI 汇报的三段式长什么样

> 🗣️ **大白话**
> 它的汇报固定分三段，方便你快速抓重点。不用全看懂，盯住"冒烟通过没"和"下一步建议"即可。

通常包含：**做了什么**（改了哪些文件）、**结果**（命令跑出来什么、冒烟过没过）、**下一步建议**（它建议接着做什么，但不会自动去做）。

### 它会在这些时候停下来主动问你

- 一个阶段全部小任务做完、要进下一阶段时；
- 要跑真正的训练 / 用全量数据 / 吃大显存的命令时；
- 发现数据缺字段、或 Excel 结构和数据规范对不上时；
- 要装规定清单之外的软件、要改既定架构、要做不可逆操作时。

> 📎 万一它**没停、想一口气往下做**，你可以直接打断，提醒它"**按 FLOW 一次只做一个任务，做完停下等我确认**"。

## 9. 名词小词典（给没有计算机背景的同学）

> 🗣️ **大白话**
> 下面是文档里会反复出现的词，用最日常的话解释一遍。看到不懂的词就回来查。

| 名词 | 大白话解释 |
|---|---|
| **GPU / 显卡** | 电脑里专门做"大量并行计算"的部件，训练 AI 模型主要靠它，比普通 CPU 快很多。 |
| **显存** | 显卡自己的内存。我们这张 4060 只有 8G，比较小，所以一次能处理的数据量有限。 |
| **conda 环境** | 给一个项目单独隔出来的"软件工具箱"，避免不同项目的工具版本互相打架。 |
| **训练 vs 推理** | **训练** = 让模型看大量历史数据、自己总结规律（慢、费机时）；**推理** = 拿学好的模型去预测新情况（快）。 |
| **batch（批大小）** | 模型一次同时看多少条数据。显存小就只能调小。 |
| **epoch（轮次）** | 把全部训练数据完整过一遍叫一个 epoch，通常要过几十遍。 |
| **冒烟测试** | 用很少的数据快速跑一两下，只验证"代码不报错、能跑通"，**不追求结果好坏**。像新电器先通电两秒看冒不冒烟。 |
| **参数（旋钮）** | 模型内部可调整的"旋钮"数量，越多越复杂。我们的模型约 **190 万个**，在 AI 里算很小巧。 |
| **张量（tensor）** | 多维的"数字表格"，是模型处理数据的基本形式。我们的数据形状是（批大小，96 个时刻，20 个水深层，23 个指标）。 |
| **loss（损失）** | 一个数字，衡量模型当前预测得有多差。训练就是想办法让它越来越小。 |
| **Parquet** | 一种又小又快的数据文件格式，比 Excel 高效得多。 |
| **Git** | 给代码做"存档和版本管理"的工具，可随时回到之前的版本。我们**只在本地用，不往网上传**。 |
| **Hydra** | 管理"配置"的工具，改参数（换显卡、改批大小）时只改配置、不动代码。 |
| **MLflow** | 记录每次实验"用了什么设置、结果如何"的工具，方便对比。我们**只在本地用**。 |
| **ONNX** | 一种通用的"模型打包格式"，方便把训练好的模型搬到现场电脑上跑。 |
| **Backbone（主干）** | 前面说的"共用大脑"，负责把原始数据加工成统一的表征。 |
| **任务头（head）** | 接在主干后面的"专项小助手"，各做一种预测。 |
| **Cline** | 一个 AI 编程助手，住在代码编辑器里，你用中文给它派活、它帮你写改代码。 |
| **归一化** | 把不同量纲的指标（比如温度和浓度）缩放到差不多的范围，方便模型学习。 |

## 10. 常见问题（FAQ）

> 🗣️ **大白话**
> 下面是大概率会遇到的问题和应对办法。遇到拿不准的，把屏幕上的报错信息原样发给负责人即可——**报错信息是最有价值的排查线索**。

**Q：装环境时装一半报错了怎么办？**
A：按文档里的顺序**一件件装**，卡在哪一步就把那一步的报错发出来排查，不要一次性全装、也不要跳过报错继续往下装。

**Q：验证 GPU 那条命令输出了 `False`？**
A：说明 torch 没装成 GPU 版，或显卡驱动 / CUDA 版本不匹配。**先别继续**，把完整输出发给负责人。

**Q：图表里的中文变成了一个个方框？**
A：正常现象——本机缺中文字体。所以我们规定**图表标注一律用英文**，按规矩来即可。

**Q：跑训练时报 `CUDA out of memory`（显存不够）？**
A：**先调小批大小**或序列长度，不要一上来就怀疑代码。8G 显存比较小，这很常见。

**Q：担心 AI 把后面的步骤一口气都做完、跑飞了？**
A：规矩里写了它每个阶段做完**必须停下等你确认**。万一它没停，直接打断并提醒它"按 FLOW 一次只做一个任务"。

**Q：数据能传到网盘 / 云端备份吗？**
A：**不能。** 数据涉密，规矩里禁止任何外发；备份也只能用本地或离线介质。

**Q：我不懂代码，能看懂 AI 的汇报吗？**
A：它的汇报是三段式中文，你**重点看"冒烟是否通过"和"下一步建议"两项**就够了，其余可以略读。

**Q：本地 4060 能跑完整训练吗？**
A：本地主要用来**写代码 + 冒烟测试**。完整的大规模训练建议去**租用 A100** 平台跑——换平台只改一个硬件配置选项，代码不动。
