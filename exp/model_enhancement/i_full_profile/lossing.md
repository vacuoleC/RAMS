# I 预测全剖面 · 边界决策记录（lossing.md）

## 与原任务意图的理解偏差
- 原任务（M1 预测全剖面 20 层）：验证正式模型是否该把输出从表层单层扩到全剖面 20 层，
  核心是"预测全剖面是帮助还是拖累表层"，以及"全剖面重建质量如何"。
- 探索设计对齐：surface（当前做法）/ full（全剖面）/ key（关键层）3 变体同一协议对照，
  不改变输入/协议/架构骨架，只改 M1 输出目标维度——忠实于原意图。

## 效果偏差（探索 vs 原方案的差异点）
- 原方案设想可能直接改冻结 RamsNet 的 M1 头输出维度。但冻结架构的 Trainer/MultiTaskLoss
  的 M1 分位数损失只支持单层目标（reshape (-1,3,H) 无法广播到多层）→ 不得不在 run_i.py
  内复制冻结训练协议。**实现一致**：冒烟验证 surface 变体（我的复制训练循环）与 B7/C 基线
  （冻结 Trainer）逐位一致（同窗口 CRPS 2.4357 / 覆盖 0.662 / RMSE 5.859）。
- 唯一变量 = M1 输出层数；共享 backbone / M2 / M4 / 权重 / 优化器 / 批次全部一致。

## 可能的损失与损失的必须
- 损失：full 变体的 M1 头参数量是 surface 的 20 倍（Linear(hidden, 3×20×H) 的权重行数），
  若"多任务共享"假说失败，full 的表层精度可能被稀释——这正是本探索要回答的问题，
  损失是**验证所必须**（对照组就是 surface 基线）。
- 损失：全剖面重建 RMSE 是副产品指标（无既定基线可对照，因为此前无全剖面预测模型），
  只能给绝对水平 + 层间相对形态，不能判定"好/坏"——但可以判"表层是否被拖累"（主问题）。
- 无数据损失：结果只写聚合统计量，不写原始数据行（保密红线）。

## 边界判定
- 探索与总方向（M1 全剖面预测、模型增强）真实意图一致，未偏离。
- 若 full 表层 CRPS 显著劣于 surface → 正式模型不扩全剖面输出（边界：另作重建任务或保持单层）；
  若 full/key 不劣甚至更优 → 正式模型可考虑全剖面输出（多任务共享收益）。
