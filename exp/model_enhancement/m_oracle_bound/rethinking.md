# M 方向：oracle 信息上限探针 · 思考记录（rethinking.md）

## 任务意图（世界观验证）
当前增量模型 CRPS≈0.86（相对持久化 +21~24%）。我们要回答一个世界观问题：
**藻类浓度在这个单站数据下的可预测上限在哪？我们接近了吗？**
- 世界观 A（接近上限）：数据可预测信息有限，继续优化收益递减
- 世界观 B（没接近）：数据有信号但方法没提取到
- 世界观 C（中间态）：平稳期接近上限，暴发期有空间但被评估掩盖

方法：oracle 上限探针——给模型输入"未来 N 天的真实 conc 值"（正常推理不可能有），
看 CRPS 能降到多少。这个数字就是数据在当前特征集下的可预测上限。

## 关键设计决策

### 1. 探针视界 H=64（8 天）而非 H=8 —— 防退化
若保持 H=8（1 天）：oracle N≥1 天就**完整覆盖目标窗**（目标 = conc_{t+1..t+8}，
oracle 给 conc_{t+1..t+8} 全在里面）→ 所有 oracle 档 CRPS≈0（退化，无信息量）。
H=64（8 天）使 oracle 只覆盖前 N 天，后 8−N 天是"诚实"预报区：
- N=1/3/7 才有可区分的读数；
- 能测"轨迹信息随视界的衰减"（已知 1/3/7 天轨迹，预报 1 天前能降多少）。

**代价**：H=64 共享骨干会把 64 个视界摊到同一 GRU，稀释短视界精度
（窗口 1 实测：base8 H=8 CRPS=2.44 vs base64 第 1 天 3.13，稀释 1.28×）。
**不影响判定**：所有 oracle 臂同 H=64，对称可比；绝对锚定由 base8 臂提供
（与公开基线 CRPS≈0.86 同协议可对照）。这不引入偏向任何世界观的偏差。

### 2. oracle 注入：通道 + 头注入（收紧信息上限估计）
光把未来 conc 作为额外输入通道给 GRU，模型在 30 epoch 内不一定学会利用它
（首次 probe：oracle_7 CRPS_all 只从 3.72→2.90，已知段复制不完美）。
改进：**把 oracle 通道末时刻值直接拼接到 M1 头输入**（hidden ⊕ oracle 通道）。
这样已知段（h≤M）的"复制"变成近线性操作，模型几乎必然用足 oracle →
信息上限估计不被"模型没学会用"低估。这是诊断工具，非部署模型。

### 3. 有效指标：已知天标 0，诚实尾用模型
模型复制已知段不完美（如 oracle_7 已知 7 天 CRPS 还有 2.39），但这**不是信息上限**
（已知轨迹 → 逐天完美点质量分布是可达的）。所以：
- **有效按天 CRPS**：已知天（h<M）标 0（可达的信息上限），诚实尾（h≥M）用模型读数。
  这是"信息上限"的正确读数。
- 保留 raw known_crps 作为"通道利用诊断"（模型离完美复制多远，反映 30 epoch 够不够）。

### 4. arm 设计（隔离变量）
- **base8**（H=8 全特征）：锚定公开基线 CRPS≈0.86（同协议同模型架构）
- **base**（H=64 全特征）：当前模型扩展到 8 天（无 oracle 的参照）
- **ar_only**（H=64 仅 conc 历史）：**强自回归上限**——把"自回归信息"隔离出来，
  base 相对它的增益才是"非自回归信号"（temp/气象贡献）
- **oracle_1/3/7**（H=64 全特征 + 未来 1/3/7 天真实 conc）：信息上限档

### 5. 关键判定数字（世界观）
- **1-day-ahead 阶梯**（同难度、不同已知轨迹长度）：
  base_d1（已知 0 天）vs oracle_1_d2（已知 1 天）/ oracle_3_d4（已知 3 天）/
  oracle_7_d8（已知 7 天）→ 每多知道 1 天真实轨迹，1 天前预报能降多少 = 轨迹信号量。
  提升小 → 轨迹对未来 Δ 的信息少（世界 A/C）；提升大 → 信息多没被提取（世界 B）。
- **base_d8 vs oracle_7_d8**（固定目标第 8 天，已知轨迹 0 vs 7 天）：
  差 = 未来 7 天未知的固有代价，不可桥接。
- **base vs ar_only**：temp/气象给多少增益（非自回归信号量）。
- **World C 检验**：逐窗口 base_d1 − oracle7_d8 差距 vs 浓度波动。若差距在暴发窗口
  显著大于平稳窗口 → 世界 C（暴发期有空间但被评估掩盖）。

## 预期与反预期
- 若 oracle 提升 <20% → 世界 A/C（接近上限，继续优化收益递减）
- 若 oracle 提升 >50% → 世界 B（数据有大量信号没被提取）
- 若 ar_only ≈ base → temp/气象对 Δ 无贡献（与 E/M5 负结果一致：藻类自回归主导）
- 反预期风险：oracle 提升被"模型用不充分"低估 → 头注入缓解；仍保留 known_crps 诊断

## 执行前验证记录（2026-08-10）
- 冒烟 1 窗口 × 2 epoch：全链路通过
- 窗口 1 × 30 epoch（CPU 诊断）：
  - base8 H=8 CRPS=2.2989（±0.12，3 seed）；base64 第 1 天 3.04、第 8 天 3.89
  - oracle_7 有效 CRPS：d1-d7 标 0，d8=2.69（vs base d8 3.89）→ 已知 7 天轨迹让
    第 8 天预报从 3.89→2.69（-31%），这是 7 天轨迹携带的信号量
  - ar_only 第 1 天 2.63 vs base 3.04 → 30 epoch 下 temp/气象反而使 1 天前预报更差
    （-14%）：**藻类 24h Δ 几乎完全由自回归历史携带**，与 E/J/M5 一致
  - 1-day-ahead 阶梯（窗口 1）：known0 3.04 → known1 2.69（-11.6%）→ known3 2.88
    （-5.5%）→ known7 2.69（-11.6%）：**多知道 1 天真实轨迹只给 1 天前预报 ~10% 增益**，
    信号几乎全在"当前已知浓度 → 明天"（自回归），继续往未来给轨迹无额外信息
  - 单窗口已倾向世界 A/C：即使 oracle 给足未来轨迹，1 天前预报也只能从 ~3.0 降到
    ~2.7（-10%），且第 8 天不可桥接代价高达 +1.2 CRPS

## 关键方法迭代（v1 → v2：掩蔽已知段损失）
首次全量（未掩蔽）暴露探针设计缺陷：oracle 臂在 loss 上主要学"复制已知轨迹"，
复制任务占主导稀释了诚实尾（未知段）的训练 → **探针低估信息上限（假世界 A 偏置）**。
证据：oracle_1 已知第 1 天 raw CRPS=0.81（应≈0），oracle_7 已知段 CRPS 0.94。
**v2 修复**：oracle 臂 M1 分位数损失只算诚实尾（h≥M）——已知段信息上限=完美复制
（CRPS=0）不占训练容量；评估用有效按天 CRPS（已知天标 0，诚实尾用模型），保留
known_crps 作通道利用诊断。这是"探针收紧"，让 oracle 数字成为紧的信息上限估计。

## 执行后实证（2026-08-10 H100 全量 6 arm × 3 seed × 17 窗口 × 30 epoch，掩蔽版 31.8 分钟）

**核心结论：World A/C——接近信息上限。oracle 给足真实轨迹也无法把 1 天前预报降到
当前模型以下。**

1. **协议可信**：base8 精确复现 A 方向 multi arm（CRPS 0.8912 / persist 1.1281 / +21%）。
2. **1 天前预报 oracle 阶梯（同难度，关键数字）**：known0 0.949 → known1 1.132 →
   known3 1.111 → known7 1.115。**多知道 1~7 天真实轨迹不降低 1 天前 CRPS（反而略升
   -17~-19%）**——"用过去轨迹预测明天"的可提取信号已被当前模型提取完。
3. **纯自回归已达最优**：ar_only（仅 conc 历史）第 1 天 0.872 < 全特征 base 0.949
   （temp/气象 −8.8%）；全 8 天 1.280 vs 1.381（−7.3%）。特征对 24h Δ 是噪声，
   与 E/D/J/M5 四线互洽。
4. **长视界 oracle "提升"= 距离效应，不可桥接**：固定目标日 base 第4天 1.402→已知3天
   1.111（+20.8%）、第8天 1.643→已知7天 1.115（+32.1%）。这是"知道中间轨迹=离目标日
   更近"，推理时不可能有 → 不可桥接固有代价，无部署价值。正确读数看第 2 点。
5. **World C 微弱、非实质**：corr(gap, 浓度范围)=+0.750、corr(gap, conc_std)=+0.775
   （方向符合 C），但绝对幅度小——仅暴发窗口 w1（range=24.5）gap=+0.265（+8.8%），
   其余 16 个窗口 base 反而更好。暴发期"已知轨迹后预报"的空间远低于世界 B 阈值。
6. **世界观判定**：数据可预测信息已基本被提取。单站藻类 1 天前预报上限由自回归过程
   噪声决定（oracle 底 1.11 vs 当前模型 0.95，模型已更好），继续榨模型收益递减。
   建议正式定稿当前增量方案，再压误差走数据量/多站方向而非调模型/特征。
