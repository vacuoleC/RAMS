# RAMS 架构蓝图（Architecture Blueprint）

> 最后更新：2026-08-09
> 状态：基于探索性测试实证的架构决策；核心模块已在 `rams/` 实现并通过冒烟 + 真实数据训练

---

## 1. 背景与定位

RAMS（Reservoir Algae Monitoring System）是一个真实落地的水库藻类智能监测项目，五个任务全部实现：

| 编号 | 任务 | 类型 |
|---|---|---|
| M1 | 藻类浓度预测 | 回归（分位数输出） |
| M2 | 热分层识别 | 分类 |
| M3 | 垂向监测点位优化 | GAT + 贪心（后续） |
| M4 | 藻华预警分级 | 分类（后续） |
| M5 | 机理与时滞分析 | PCMCI+（后续） |

**2026-08 需求更新**：
- 推理环境算力充足（非工控机），正式训练用 8×H100（sensecore 平台，可扩容）
- 追求**最大精度**（替代原轻量化约束）
- 定位：真实落地的基层科研工作，用前沿工具在现有真实数据上发挥到极致
- 第一版**不追求跨站可迁移性**，集中火力做好单站 5 个任务

## 2. 数据实况（探索测试实证，2026-08-09）

| 项目 | 实测值 | 对设计的影响 |
|---|---|---|
| 藻类行数 | 258,542（20 层 × ~12.8k 行） | 每层完整时序 |
| 时间范围 | 2021-03-01 ~ 2025-09-30 | 约 4.5 年 |
| 藻类采样间隔 | **1-5 小时**（非文档声称的 3h） | 时间对齐需注意 |
| 气象采样间隔 | **10 分钟** | 需重采样对齐 |
| 各深度层时间戳 | **错位 4-5 分钟，精确交集=0** | 必须 floor 到 3h 网格 |
| 3h 网格对齐后 | 97.8% 深度层对齐 | floor 后可用 |
| 缺失率 >5% 列 | 无 | 数据质量好 |
| `cyano_conc` 分布 | p50=0, p95=3.89（极度偏斜） | 藻华事件稀少 → 需分位数/不平衡处理 |

**关键数据决策**：各深度层时间戳精确交集为 0，必须先把藻类 `timestamp` floor 到 3h 网格，再与气象 `merge_asof`（nearest, 容差 3h）对齐。

## 3. 架构决策（探索测试实证，3-seed 验证）

### 3.1 已验证的结论

| 假说 | 结论 | 证据（3-seed 均值±std） |
|---|---|---|
| **垂直信息价值** | ✅ 20 层输入比单层降误差 **32%** | 单层 6.44±0.25 → 20 层 4.36±0.12 |
| **共享 backbone + 多任务** | ✅ 比单任务再降 **8-15%** | 20 层单任务 4.36 → 多任务 4.02/3.72 |
| **M2 高权重** | ✅ 分类优先（w2=3.0）最优 | 归一化 4.02 → 分类优先 3.72 |
| **分位数输出** | ✅ RMSE 不损失 + 区间校准好 | 覆盖率 80.9%（探索）/ 85.0%（正式） |
| **loss 归一化** | ✅ 时序任务下必须做 | 未归一化 4.29 vs 归一化 3.79（P4） |
| **GRU vs LSTM** | GRU 略优 | GRU 4.26 vs LSTM 4.89（P2） |

### 3.2 架构蓝图

```
Input (B, T=24, D=20, C=26)
   ├── 20 层水温（temp_0.5 ~ temp_10.0）
   └── 6 气象（wind_speed/dir, pressure, air_temp, humidity, rainfall）
        │
        ▼
共享 GRU Backbone (hidden=64, 1 层)
   └── 末时刻隐状态 (B, 64)
        │
        ├── M1 头（MLP）→ 分位数输出 (B, 3×H)  [p10/p50/p90]
        └── M2 头（MLP）→ 分层分类 (B, 2)
```

**多任务损失**：`L = w_m1 × L_quantile(M1) + w_m2 × CE(M2)`，其中 `w_m1=1.0, w_m2=3.0`。

**参数量**：27,674（探索版 GRU backbone）。正式版可适度放大（数据量约束下，~1.9M 的规模已足够，不必追求大模型）。

### 3.3 关键设计选择详解

1. **为什么 20 层输入**：垂直分层数据是项目最大资产，全剖面输入比单层降误差 32%。这是整个项目的核心卖点，也是与"单点监测"最本质的差异。

2. **为什么 M2 作为多任务头而非特征旁路**：
   - 把 delta_T 当输入特征：仅 -0.9%（无效）
   - 把分层状态当辅助任务标签：-7.4%（有效）
   - 结论：**M2 应该共享 backbone、作为多任务训练**，而不是简单把分层数值塞进输入。

3. **为什么 M2 权重更高（w_m2=3.0）**：分层任务训练对 M1 预测有正则化/信息增益作用。分类优先配置（w2）得到全场最低 RMSE。

4. **为什么分位数输出**：M1 输出"预测 + 置信区间"不损失精度，且区间校准良好（85% 覆盖率 vs 理论 80%）。这是"不确定性量化"主线的基础，也是 M3 点位优化闭环（预测误差驱动的布点）的前提。

5. **为什么 loss 归一化在时序任务下必要**：第一轮当期回归实验发现"未归一化更好"是假象；在真实时序多任务下，归一化（给回归降权）显著更好。**文献共识（Wu 2022）在时序任务下被证实**。

### 3.5 M4 预警分级（2026-08-09 实现）
**架构**：共享 GRU backbone + M4Head（MLP → 四级分类），与 M1/M2 联合多任务训练。

**标签生成**：每个训练样本的"预警浓度" = 未来 24h 浓度峰值（窗口内 y 最大值）；四级阈值用**训练段**峰值浓度的分位数（p75/p90/p97）定，防数据泄漏。等级：安全/注意/警告/危险。

**实证结果**（30 epoch，真实数据）：
- M1 RMSE = 3.64（与双头 3.58 接近，多任务不拖累回归）
- M2 acc = 0.962（稳定）
- M4 测试 acc = 0.939
- 覆盖率 80.1%（校准良好）

**发现的问题**：训练时 val_wacc=0.686 但 test_wacc=0.939——验证段与测试段的预警标签分布不同（预警阈值用训练段拟合，验证段峰值偏高导致分级更稀疏）。

**类别加权处理**（2026-08-09 完善）：Trainer.fit 自动从训练段 M4 标签计算逆频率类别权重。实证对比：
- 不加权：M1 RMSE=3.64, M4 acc=0.939, 覆盖率 80.1%
- 类别加权：M1 RMSE=3.59, M4 acc=0.898, 覆盖率 87.4%
- **trade-off 解读**：加权更重视少数类（危险等级）→ 覆盖率提升、风险捕获更好，代价是整体 acc 略降。**预警场景应优先 recall（不漏报），类别加权更符合实际需求**（文献共识：M4 用 recall/F1/MCC 而非 accuracy）。

**待完善**：
- WHO/GB 5749 阈值映射（对接真实预警标准）
- 预警提前量输出（预测到哪一步达级）
- 用 recall/F1/MCC 评估 M4（而非仅 acc）

### 3.6 M3 垂向监测点位优化（2026-08-09 探索完成）

**架构**：GAT 打分器（PyG GATConv，2 层，hid=96，4 heads）+ 贪心前向选层。
- 图结构：20 深度节点 + 1 重建节点 R；在**随机深度子集**下训练（每样本 k~U[1,20] 可见层）
- 可见层重建=观测值本身（blend），loss 只惩罚隐藏层补齐误差
- 贪心：空集起，每步加"验证集剖面重建 RMSE 下降最多"的层，预算 8 层

**实证结果**（3-seed，真实数据）：
- **最优 5 层**：近表层 1 层（0.5~2.0m）+ 中层 1 层（4.5~5.5m）+ 深层 3 层（8.5~10m）；**底部 8.5~10m 几乎必选**（分层信息量大），3.0~4.0m 冗余
- 5 层测试剖面重建 RMSE ≈ 0.10°C（全 20 层 = 0），已拿走近 90% 重建收益
- 5 层 vs 无传感器（仅气象 ~1.0°C）：下降 ~90%
- 5 层 vs 均匀 5 层 / 线性插值贪心：GAT 略优或持平
- 第 1 层贡献最大（单层即压到 0.16°C，贡献 87%）；边际递减：k=2~5 收敛到 0.08°C 以下

**架构建议**：
1. **部署 5 层**即可：剖面重建 RMSE ≈ 0.10°C，成本 -75%
2. **生产版升级**：把传感器子集时序接入 SharedGRU backbone，目标改为"选层历史 → 预测表层浓度 + 重建剖面"，让选层直接服务 M1/M4
3. **重要提醒**：水温剖面近似分段线性，**线性插值是强基线**（隐藏层插值 RMSE 0.055~0.15°C），GAT 的增量在温跃层非线性补齐；做选层务必与插值基线对比，避免过度报告

### 3.7 M5 机理与时滞分析（2026-08-09 探索完成，最终版）

**方法**：PCMCI+（tigramite parcorr），12h 均值降采样 + ACF 定 τ_max + 全候选空间（不用 selected_links，避免伪边）。
- 12h 网格 3350 时刻；ACF 定 τ_max=60（30 天窗口，覆盖文献滞后上界）；ParCorr 线性检验
- 全候选空间 8640 条滞后候选 → 扫描 2400；耗时 **7.4 分钟**（H100）
- 变量 12 个：季节 sin/cos、表层总浓度、表层蓝藻、表层水温、20 层平均水温、风 u/v、气温、湿度、降雨、气压

**因果发现（全部 MCI 显著，p<0.05，含真实检验统计量）**：
- **自相关（惯性）主导**：conc_surf τ=1（0.5d）r=+0.63、cyano_surf τ=1 r=+0.57 & τ=2 r=+0.37、temp τ=1 r=+0.57
- **蓝藻中期波动**：cyano τ=5（2.5d）-0.24、τ=10（5d）+0.16（抑制后反弹的动力学）
- **气象直驱弱且短滞**：wind_u→temp_surf τ=2 r=+0.13、wind_u→cyano τ=1 r=+0.07、humidity→temp_surf τ=3 r=+0.06；**未见降水/气温/风 20-30 天长滞显著直驱**
- **水温非中介**：temp→conc 无 MCI 显著边。20-30 天处表现出的"滞后相关"（如 air_temp→cyano 原始 r=0.32@23.5d）经季节项+自回归条件化后被解释为**季节共变，非因果**（季节 sin/cos 本身对藻类/水温全滞显著）
- 修正了初版（val=0 伪边）误报的"主要通过水温中介"——该版本用 link_assumptions 剪枝引入了未过 MCI 检验的伪边，现已弃用

**核心结论**：30 天窗口内，**藻类浓度主要由自身自回归惯性驱动，气象（尤其风）短滞直接贡献弱，20-30 天"滞后"多为季节共变**。对 M1/M4 的意义：历史藻类浓度是最强预测因子；风（u 分量）可作短滞气象特征；不建议把 20-30 天滞后气象当因果特征。

**待完善**：
- CMIknn 非线性检验（慢 10-100×，验证线性近似是否漏掉非线性驱动）
- τ_max / α_pc 敏感性网格
- 与 M1 特征工程对接（因果筛选结果作为特征选择先验）

### 3.8 T1 五头整合训练（2026-08-10 完成）

**设计**：A/B/C/D 四配置 × 3 seed × 30 epoch，共用相同 train/val/test 窗口，仅特征列不同（公平对比）：
- A 基线：20 层 + 6 气象（26 特征）
- B A+wind_u（M5 短滞特征，27 特征）
- C M3 最优 5 层（近表 1.5 + 中层 5.0 + 深 8.5/9.5/10.0，11 特征）
- D M5+M3（12 特征）

**结果**（3-seed 均值±std，M1 RMSE）：

| 配置 | M1 RMSE | M2 acc | M4 acc | 覆盖率 |
|---|---|---|---|---|
| A 基线 | 3.643±0.044 | 0.948 | 0.919 | 0.842 |
| B A+wind_u | 3.567±0.063 | 0.950 | 0.925 | 0.827 |
| **C M3 5层** | **3.438±0.121** | 0.920 | 0.898 | 0.817 |
| D M5+M3 | 3.581±0.024 | 0.941 | 0.904 | 0.819 |

**结论**：
1. **最优配置 C（M3 5 层）**：M1 RMSE=3.438，比基线 A 降 5.6%。**M3 选层结论被训练端证实**——5 层（11 特征）精度 ≥ 20 层（26 特征），输入省 75% 且 M1 更好。支持部署 5 层传感器方案。
2. **M5 wind_u 边际有效不普适**：20 层基线上降 2.1%（弱信号），叠加到 5 层反而略增（+4.2%）。不建议单独加通道。
3. **整合净效果**：D 比 A 降 1.7%（主要来自 M3 选层瘦身）。纯最大精度选 C；鲁棒低方差选 D。
4. **注意**：C 配置下 M2/M4 acc 略降（0.920/0.898 vs 0.948/0.919）——5 层信息少导致辅助任务略回退，需权衡。

**对部署的意义**：5 层传感器方案不仅省 75% 成本，还是最大精度选择——M3 的"底部必选 + 近表 1 层"布点被端到端验证。

### 4.3 踩过的坑（已解决）

1. **各深度层时间戳错位**：精确交集=0，floor 到 3h 网格解决
2. **sheet 自带「深度」列**：合并前删除避免重复
3. **气象精确 merge 全失败**：须用 merge_asof 最近时刻
4. **pivot 后 258k 行**：原始行索引导致透视后 20 层互斥 NaN，先 groupby(ts3h, depth) 聚合
5. **PCMCI+ 组合爆炸**：τ_max=192 + 12 变量 = 27,648 条初始候选边，死跑 182 分钟无果。**官方确认成本∝链接数×条件数**。修复：降采样 3h→12h（物理尺度）+ ACF 定 τ_max（60）+ 全候选空间（不剪枝，保统计量真实）+ max_conds=5 → **7.4 分钟**跑完。参考：tigramite Discussion #208。
6. **link_assumptions 伪边**：用 `-?>` 剪枝后 graph 里出现大量 val=0/p=1 的 `-->` 伪边（链接进了假设但没真正跑 MCI 检验）。修复：默认全候选空间 + collect_edges 按 p<alpha 过滤。**教训：剪枝提速别用会污染 graph 语义的 link_assumptions，优先降采样+ACF。**
