# RAMS 数据合规与去标识化检查清单

> 最后更新：2026-08-10
> 定位：把"涉密数据训练 + 公开数据验证"的双轨实验设计落地为可逐项打勾的执行规范。
> 适用范围：论文发表（Ecological Informatics / Water Research / Harmful Algae 等）、公开竞赛（EFI-USGS 等）、代码开源、软著申报、任何对外输出。
> 依据：`.clinerules/00-核心规则.md` 第 5 节（保密红线）、`.clinerules/01-数据规范.md`（数据契约）、`docs/standing_plan.md` S3。

## 0 · 一句话总纲

> **涉密数据训练，公开数据验证；论文里只出现"方法 + 统计量 + 标准化/相对量 + 公开数据的结果"，绝不出现任何原始数值、站点明文、精确日期与坐标。**

三条不可破的底线（比下述清单更优先）：
1. **原始数据（任何浓度/水温/气象的原始读数）绝不外传、绝不打印、绝不入图、绝不进论文。**
2. **本地 Git 不配远程、不 push；数据与模型权重一律进 `.gitignore`；实验只用本地 MLflow。**
3. **拿不准是否涉密 → 按涉密处理，先问人再输出。**（与 `.clinerules/00` 第 12 节一致）

## 1 · 数据分级（三级）

### 1.1 三级定义与处理规则总表

| 级别 | 定义 | 例子（本项目） | 处理规则 |
|---|---|---|---|
| **A 级 · 涉密** | 可反推/暴露单站点真实监测原始值的数据与产物 | `data/raw/` 三个 xlsx、`data/processed/standard.parquet`、`norm_stats.json`、`data/interim/*`、任何含原始读数的中间文件、**涉密轨训练出的模型权重（含 ONNX）**、MLflow 本地库中的原始指标日志 | 本地物理隔离；绝不进 git / 不进论文 / 不上传任何平台 / 不打印原始值 |
| **B 级 · 去标识化** | 已无法还原单条原始读数，但仍含涉密数据统计特征的分析产物 | 归一化后的特征统计（各通道均值/分位数/时变范围）、标准化前后的分布图（轴已模糊）、**由涉密数据拟合的模型权重（见 §3.4 判断）**、SHAP/Captum 特征重要性、PCMCI+ 因果边表（如 `m5_pcmci_results.md`）、论文中所有涉密数据图表 | 可进论文正文/补充材料，但须先过 §2 清单；不进公开代码仓库；供期刊审稿人定向审阅时可走受限通道 |
| **C 级 · 公开可用** | 本不涉密或源自公开渠道的材料 | 公开数据集（太湖 THQBCA、江西水库、EFI-USGS、Tick Tick Bloom 方案）、**公开标准文本（GB 5749-2022、WHO 微囊藻毒素-LR 1 µg/L 等）**、模型架构与训练代码（不含涉密权重）、公开数据上的实验结果 | 可随论文发布/开源；需标注来源与 DOI/许可 |

### 1.2 判定原则（防"降级"错误）

- **判定标准不是"看不出单条"，而是"能否反向拼出原始数据"**。统计量可以发表，但要控制粒度（见 §2）。
- **去标识化是一个过程，不是静态标签**：任何 B 级产物被投出去之前，必须重跑一遍 §2 清单并记录检查人/日期。
- **权重升 A 级的场景**：凡模型在涉密数据上训练/微调过（哪怕只对齐了 `norm_stats`），权重一律按 A 级默认处理，除非经 §3.4 判定后走 B 级受控发布。
- **C 级不自动成立**：公开数据集也要遵守其自身许可（Zenodo/Scientific Data 的 CC-BY 等），引用要规范。

### 1.3 一个具体的 B 级负面案例（对照 `docs/m5_pcmci_results.md`）

M5 结果文档目前的做法是**合格的 B 级样例**：只报告变量名、时滞（τ×12h）、MCI 相关系数、p 值，`说明`一节明确写了"仅报告变量名/时滞/统计量，不含原始数据值"。**对照检查**：这份表里的 `wind_u`、`conc_surf` 是字段名（公开可写），相关系数是统计量（允许），但**任何一行原始浓度读数（如"某日 0.5m 蓝藻 = 12000 cells/mL"）绝不允许出现在这类文档里。**

## 2 · 去标识化检查清单（发表/开源/竞赛前逐项打勾）

> 用法：每次准备对外输出物（论文图、补充材料、竞赛提交、开源仓库）前，逐项过一遍。**全部 ✅ 才能对外**；任一项 ⚠️ 回到 §1 重分级。

### 2.1 原始数值 → 标准化 / 相对值

| # | 检查项 | 判定方法 | 处置 |
|---|---|---|---|
| 1 | 论文/图中是否出现**绝对浓度/水温/气象原始读数**（如 "chla=12.3 µg/L"、"水温 26.4°C"、"降雨 45mm"） | 全局搜索论文草稿与图源：`µg/L`、`cells/mL`、`mg/L`、`°C`、`mm` 等带单位的数字 | 一律改写为**标准化值（z-score / 0-1）、相对值（相对基线变化 %）、分位排名或归一化后的无量纲量**；需要物理意义时引用"量级区间"而非具体值 |
| 2 | 是否出现**某个具体日期的具体值对**（"2022-07-15 蓝藻浓度达峰"） | 搜索完整日期格式 `\d{4}-\d{2}-\d{2}` | 时间轴用**相对时间（第 n 天 / 距起点月数）**或模糊到月份/季节；单点报值改为"该时段分位数" |
| 3 | 是否出现**水文/气象联动具体值**（如"风速 8.3 m/s 时浓度 XX"） | 人工审图审表 | 二元/多元关系只以统计量（相关系数、PCMCI 边权）呈现，不呈现具体样本点 |
| 4 | 统计量本身的粒度是否过细 | 检查是否报了大量**高分辨率分位数**（如每层每日 P95） | 聚合到日/周/月级别的汇总统计；单站 20 层的分布可以报**分层区间**，不报逐层逐时刻序列 |

### 2.2 站点信息（0902、坐标、位置）

| # | 检查项 | 判定方法 | 处置 |
|---|---|---|---|
| 5 | 正文/图/代码/日志是否出现**站点编号 0902**（含 `"0902"`、`site_id` 的真实值） | 全局搜索 `0902`、`site`、`site_id` 的值 | 论文中统一称"a single reservoir in southern China / 某南方水库"；代码开源版把 `site_id` 换成 `"SITE_A"` 占位符 |
| 6 | 是否出现**经纬度坐标 / 地图定位 / 行政地名**（水库名、乡镇名、监测站名称） | 搜索坐标格式、地图图、中文地名 | 一律隐去；如需描述气候带，只写大区域（如"亚热带季风区"）不写具体城市/流域名 |
| 7 | 图里是否隐含**空间位置可识别**信息（如布点优化 M3 图中画出水库轮廓/实测点位相对坐标） | 审 M3 点位图、传感器部署图 | M3 的深度布点结论**可以发表**（"在 1-3m 布 3 层最优"），但任何把点位映射回真实地形/水域的底图不得出现；用抽象深度轴代替 |

### 2.3 时间信息（精确日期）

| # | 检查项 | 判定方法 | 处置 |
|---|---|---|---|
| 8 | 是否暴露**精确到日的采集时段**（2021-03-01 ~ 2025-09-30） | 全局搜索日期范围 | 论文可写"four-year period（2021–2025）"年份区间；避免精确起止日；数据声明里如需给时段，只给年份跨度 |
| 9 | 时序图 x 轴是否为**精确日期** | 审所有时间序列图 | x 轴改为相对时间（第 n 天 / 年-月）或模糊到月；不标出"2021-03-01"这类锚点 |
| 10 | 是否暴露**采样频率的敏感组合**（能推断监测制度） | 审方法论描述 | 采样间隔可以写（10 min 气象 / ~3h 藻类），但要避免"每周一 9:00 人工采样"这类可识别监测站运维流程的描述 |

### 2.4 图表（图注、轴标签、数据点）

| # | 检查项 | 判定方法 | 处置 |
|---|---|---|---|
| 11 | **图注/图例/轴标签**是否含站点名、精确日期、原始单位的具体值 | 逐图人工审（图注最容易漏） | 轴标签一律无量纲或"relative"；图注不写站点/日期 |
| 12 | **散点/分布图的数据点**是否过密到可反推原始序列 | 若某图样本点数 ≈ 原始行数（如 258k 点） | 用聚合图（密度/箱线/热力）+ 降采样；散点最多报告抽样点，且坐标已标准化 |
| 13 | **预测 vs 真实对比图**（M1 的 RMSE、覆盖率图）中真实值是否以原始读数呈现 | 审所有 loss/拟合曲线图 | 纵轴标准化；不出现原始浓度刻度；RMSE 等单位标成"normalized RMSE" |
| 14 | 热力图/分层图（M2 热分层）色标是否绑定原始温度/浓度值 | 审色标 legend | 色标用标准化值或层级标签（"stratified / mixed"），不印原始量纲 |
| 15 | **图是否作为独立文件散落在 docs/notebooks** 且文件名含敏感信息 | 检查 `docs/*.png`、`notebooks/` 导出图 | 对外目录只放通过检查的图；文件名用 `fig3_transfer_rmse.png` 这类，不用 `2021-2025_0902_*.png` |
| 16 | 补充材料/附录中的大表是否含原始数据行 | 检查 `tableS*` | 大表只放统计量（均值±std、分位、效应量），不放原始行 |

## 3 · 双轨实验设计规范

### 3.1 总体架构

```
                ┌─────────────────────────────────────────────┐
   涉密轨（本地）│  standard.parquet ──→ RAMS-Net 训练/微调      │
                │  MLflow 本地追踪（不采样原始值日志）          │
                │  产出：权重(涉密默认A) + 特征重要性 + 因果边    │
                └─────────────────────────────────────────────┘
                              │ 只带出"方法 + 统计量 + 标准化量"
                              ▼
                论文正文 / 补充材料（B 级，过 §2 清单）
                              ▲
                ┌─────────────────────────────────────────────┐
   公开轨（开放）│  太湖/江西水库/EFI-USGS 公开数据 ──→ 验证泛化   │
                │  产出：跨数据集迁移/基线对比结果（C 级可发布）    │
                └─────────────────────────────────────────────┘
```

### 3.2 涉密轨规则（本地，不外发）

- 数据入口只有 `data/processed/standard.parquet`；`scripts/build_dataset.py` 是唯一读 xls 的地方，只跑一次。
- 训练/实验只在**本地或可信内网**机器跑；**禁用 W&B、Kaggle、Colab、sensecore 等任何云端平台跑涉密数据**（租用 H100 前须与数据所有者确认该算力环境属于可控范围——本清单建议**默认不在任何外部租用平台上放涉密数据**）。
- MLflow 日志项**只记录指标（loss、RMSE、覆盖率）与超参，不记录样本值、不记录真实日期对应关系**；`mlruns/` 已在 `.gitignore`。
- 涉密轨产出物中，**只有"方法描述 + 统计量 + 标准化量 + 因果结构（无原始值）"可被携带到论文**。

### 3.3 公开轨规则（开放，可发布）

- 公开轨数据来源（按 standing_plan S1）：EFI-USGS 河流叶绿素挑战赛（持续开放）、太湖 THQBCA（Zenodo, Scientific Data 2024）、江西水库（Scientific Data 2026）、LAGOS-US、CyAN/CGLS 遥感、Tick Tick Bloom 冠军方案（arXiv 2505.03808）。
- 公开轨**独立于涉密轨运行**：验证"方法/架构在公开数据上同样有效"，证明泛化能力。
- 公开轨结果 = C 级，可随论文发布、可进公开竞赛提交。引用公开数据集时必须附 DOI 并遵守其许可。
- **公开轨与涉密轨之间的"隔离契约"**：
  - 允许共享：模型**架构**（不含权重）、归一化**方法**（不共享涉密轨拟合的 `norm_stats.json` 参数值）、训练超参、特征工程**逻辑**。
  - 禁止跨越：涉密轨**权重**不得直接用于公开轨发布；公开轨**不得反向拟合**涉密统计量（不能拿"论文里的 P95"去重建分布）。
  - 两轨各自独立的统计检验（3 seed × Wilcoxon），公开轨的显著性可以发布，涉密轨的显著性**只发统计量、不发明细**。

### 3.4 关键判断：模型权重能否发表？

**判断：涉密轨训练的模型权重默认属于 A 级，不建议公开发布。** 理由与边界：

- **技术上**：模型可能记忆训练样本（成员推理/提取攻击在深度学习模型上已被反复证实）。即使本项目是 1.9M 小模型、回归/分类任务，泄露风险低于大模型，但"小 ≠ 零"——尤其 M1 输出与训练目标高度相关，权重 + 归一化参数 + 公开特征范围三者拼起来，可能反推原值量级。
- **合规上**：数据是**第三方/上级提供的涉密数据**时，你未必拥有"以模型形式转授权"的权利——这是数据所有者常主张的越权点。**发布权重前必须取得数据所有者的书面许可。**
- **惯例上**：行业对"涉密数据训出的权重"普遍按 IP 保密处理（发布方法、不发布权重），这与本项目保密红线一致。
- **结论与建议**：
  1. **默认不发布**涉密轨权重；论文只描述架构与训练方法。
  2. 若数据所有者书面同意 + 需求明确（如软著/部署演示），可考虑：
     - 发布**压缩/量化后**的 ONNX 权重且附"仅演示，勿反推"声明；
     - 或发布**公开轨重训的等价权重**（公开数据 → 同架构权重）作为可复现替代物。
  3. **若完全不发布权重**，在论文数据可用性声明里写明"权重因数据保密不对外发布，可联系作者在数据所有者许可下定向提供"——这符合多数期刊对 proprietary/restricted data 的豁免口径（见 §4.2）。
- **可发表的"模型侧"内容**：参数量、层结构、FLOPs、训练曲线（标准化轴）、跨数据迁移表现——这些都不涉及权重本体。

### 3.5 两轨边界速查：什么能进论文 / 什么不能

| 内容 | 能进论文？ | 形式要求 |
|---|---|---|
| 涉密数据训练出的 RMSE/acc/覆盖率 | ✅ | 仅统计量；若报 RMSE 用 normalized RMSE 或相对提升，不报绝对浓度误差量纲 |
| 涉密数据的 M1-M5 结果图 | ✅（B 级） | 过 §2 全部图表检查（轴标准化、无站点/日期/原始值） |
| SHAP / Captum 特征重要性 | ✅（B 级） | 只报相对重要性排序/百分比，不报"某特征在某具体值区间对预测的影响数值"（见 §5.1） |
| PCMCI+ 因果边 | ✅（B 级） | 只报边、时滞、r/p（对标 m5_pcmci_results.md 现有做法） |
| M3 布点优化结论 | ✅ | 报"哪几个深度层最优"，隐去坐标与水库底图 |
| 涉密数据**原始行 / 原始值 / 精确日期 / 站点 / 坐标** | ❌ | 一律不进 |
| 涉密轨**模型权重** | ⚠️ 默认❌ | 除非数据所有者书面许可 + §3.4 建议路径 |
| 公开数据上的全部结果 | ✅（C 级） | 照常发布，附数据集 DOI 与许可 |
| 模型架构 / 训练代码（脱敏版） | ✅（C 级） | 路径、站点、日期、统计量常量全部占位符化（过 §2.5） |

## 4 · 投稿合规流程（国际期刊 / 公开竞赛）

### 4.1 投稿前步骤（走完才投）

1. **§2 清单全绿**：把论文初稿 + 全部图 + 补充材料 + 开源代码打包，逐项过清单并填 §2.6 记录表。
2. **数据所有者书面确认**（最重要的一步）：由数据提供方/上级单位确认
   - 论文中可披露的统计量/去标识化内容范围；
   - 是否同意发布"由涉密数据拟合的统计量 + 方法"；
   - 是否同意发布权重（默认不同意，见 §3.4）。
   - 建议把"拟发表内容清单 + 去标识化方式"一页纸发数据所有者审批并留书面回执。
3. **机构审批**：按所属单位科研管理规定走论文发表审批/保密审查（若数据来自政府/行业监测，可能涉及保密审查流程，须在投稿前完成）。
4. **预演可复现性**：准备"可复现路径"——公开数据上的完整跑通脚本 + 涉密数据上"数据结构说明（列名/类型/维度）但不含数据本身"的 schema 文档 + 归一化方法说明（不泄露拟合参数）。
5. **确认目标期刊的 DAS 要求**：投稿前查期刊 Guide for Authors 的数据政策（Elsevier/Springer/Wiley 均要求 Data Availability Statement，且支持受限数据豁免；如 Ecology 类期刊常要求数据可获取，需准备豁免理由）。

### 4.2 数据可用性声明（Data Availability Statement）模板

目标期刊要求 DAS 时，从下面组合使用（**声明全文在投稿前过一遍 §2**，与正文措辞保持一致）：

> **中文版（供内部确认，不进论文）：**
> 本研究中使用的涉密水库监测数据受保密协议约束，不对外公开。论文所报告的结果均为去标识化的统计量，原始数据不随论文发布；符合条件的研究人员可在数据所有者的书面许可下，联系通讯作者申请定向获取经去标识化的数据摘要。模型权重因涉密不对外发布。公开验证数据集的来源与 DOI 已在数据可用性声明中列出。

> **英文版（进论文）：**
> **Data availability.** The reservoir monitoring dataset used to train the models is confidential and proprietary; raw data are not publicly available due to confidentiality restrictions. De-identified summary statistics and the model methods are fully described in the manuscript and its supplementary materials. Researchers may request access to the de-identified data summaries from the corresponding author upon reasonable request and subject to the data owner's written permission; trained model weights are not released for the same reason. Public datasets used for external validation are available from their original repositories: THQBCA [DOI], Jiangxi reservoir dataset [DOI], EFI-USGS challenge [URL], and follow their respective licenses.

> 可选补充句（期刊若要求可复现路径）：
> To support reproducibility, anonymized code with placeholder paths and the public-data pipeline are provided in [Zenodo/Figshare/... DOI]; the sensitive pipeline requires local data access and is described in the Supplementary.

**要点**：DAS 里只承诺"去标识化数据摘要可申请"，**不要承诺"原始数据可申请"**（原始数据连你自己都不外传）；权重不发布这条要明说，避免审稿人误以为缺省可提供。

### 4.3 公开竞赛注意事项

- 竞赛提交前核对：**不夹带任何涉密文件**（权重、parquet、xlsx、日志、截图）；提交物 = 预测结果 + 方法描述。
- 竞赛若要求"全部数据开放/复现"，优先用公开轨数据跑通；涉密轨结果只在方法层面描述。
- 记录竞赛条款是否要求 IP/代码归属——若要求开源权重，则默认不参加或先过 §3.4 决策。

## 5 · 常见风险与规避（细节清单）

### 5.1 SHAP/Captum 图会不会泄露特征分布？

**会，如果图里带上了原始特征坐标。** SHAP 依赖图（dependence plot）的 x 轴就是特征原始值，y 轴是 SHAP 值——直接把"水温=26.4°C 时蓝藻 SHAP 升高"这种图发出去，等于公布了原始水温取值。规避：

- 依赖图 x 轴改用**标准化特征值**（z-score），或把 x 轴模糊为低分辨率区间（"水温分位段 1/2/3"）。
- 只报**特征重要性排序 + 平均绝对 SHAP 相对占比**（"wind_speed 重要性 0.18，排第 3"），不报具体取值处的作用量。
- 对涉密轨 SHAP 一律按 B 级处理；若审稿人索要 SHAP 依赖原始图，走受限审阅通道（见 §5.6）或拒绝并提供标准化版。

### 5.2 PCMCI+/因果边权会不会泄露？

**边 + 时滞 + 相关系数不会**（对标 `m5_pcmci_results.md` 现做法）。**会**的是：把"某时刻的具体序列片段"或"某变量在该水库的绝对量级"混进因果叙述。规避：因果图只画节点+边+时滞；叙述里不出现任何绝对浓度描述。

### 5.3 聚类/分布图泄露？

降维图（PCA/t-SNE/UMAP）若给每个点标注真实采样时间或把坐标映射回原始特征空间，可反推结构。规避：聚类结果只报簇数/簇间统计差异；坐标轴为降维主成分（本身已去标识化），不叠加真实日期/浓度刻度。

### 5.4 模型权重记忆 / 提取攻击

即使权重不发布，也要防**部署侧泄露**：推理 API（FastAPI）若接受任意查询并返回高精度原始量纲预测，攻击者可用大量查询做"蒸馏/重建"。规避：部署接口返回分级/预警/相对量而非原始浓度；对查询频率限流；明确该部署仅内部使用。

### 5.5 统计量足够多时"马赛克攻击"

大量独立统计量（如 20 层 × 4 年 × 各分位数）拼起来可重建分布。规避：对外只给**聚合粒度的统计量**（全局分位数、年/月级均值）；每个统计量按 §2.1-4 判粒度；对"论文中出现的所有统计量"做一次整体审视（防止每个单看没事、合起来能拼）。

### 5.6 审稿人 / 编辑索要涉密数据

- **常规动作**：拒绝并提供 DAS + 可复现路径（公开数据跑通代码 + schema 说明 + 去标识化摘要）。
- **期刊"confidential review"机制**：部分期刊允许把受限数据仅供编辑/审稿人审阅而不公开。若走此通道，需数据所有者额外书面同意 + 签保密协议，且只给**去标识化摘要**（给"数据摘要"而非原始数据，仍然最安全）。
- **硬性拒绝原则**：无论谁索要，原始数据一律不给，只给 B/C 级材料；解释理由（第三方涉密 + 无转授权）。

### 5.7 图表文字/元数据残留

PNG/PDF 的元数据（作者、电脑名、路径）也可能泄露。规避：导图时清理元数据；文件名不含站点/日期/原始值；PDF 提交前检查属性。

### 5.8 代码注释与 README 的"顺手"泄露

注释、README、issue、commit message 里最容易出现真实站点/日期/路径。规避：提交前 `grep -rn "0902\|2021-03\|藻类检测数据\|D:\\\\coding"` 于待提交内容；commit message 也不写敏感细节（当前规范已要求中文简述）。

## 6 · 配套机制（落地保障）

1. **检查脚本**（建议实现）：`scripts/compliance_check.py` 扫描待发布目录，自动抓 §2 的关键模式（`0902`、完整日期、`µg/L|cells/mL|°C` 带数字、`.xlsx|.parquet|.pt|.onnx` 文件、`data\` 绝对路径、`print(` 后跟 `df|head`），输出风险清单供人工复核。冒烟即可，不跑全量。
2. **对外发布目录约定**：`release/`（或 `dist/`）为**唯一可对外打包目录**，只允许放 C 级文件 + 通过 §2 的 B 级文件；对外打包一律从这里取，不允许直接从 `docs/`、`notebooks/`、`rams/` 抓文件。
3. **分级标注**：`configs/data/schema.yaml` 每列加 `compliance: A|B|C` 字段；代码中新增任何字段先定级。
4. **本文档维护**：每次对外输出后回填 §2.6；每半年/每次投递前重读一遍本文档与 `.clinerules/00` 第 5 节。
5. **红线不因便利而松**：任何"暂时先传一下 / 就一张图"都按涉密处理；拿不准就按 A 级。
