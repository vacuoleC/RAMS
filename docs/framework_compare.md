# RAMS 模型框架比较：GRU 是否最优？

> 统一接口公平对比：同一数据（20 层水温 + 6 气象，T=24 回看 → 预测未来 24h 表层浓度）、同一时序切分（70/15/15）、同一评估（测试集 RMSE 还原原始尺度）、torch 模型同一训练量（30 epoch × batch128 × Adam lr1e-3）。只输出统计量，不涉原始数据。

数据：12 个模型 × 3 seed，y_sd=13.8860

> **持久化基线说明**：任务书的「已知 12.96」来自早期脚本误算（持久化成了首特征 temp_0.5 水温，非浓度目标，见 `t2_public_baseline.md`）。本实验按正确口径（窗口最后观测浓度）在测试段得到约 1.2-2.1。

## 结论

- **全局最低 RMSE**：`持久化`（1.230±0.000）——这是持久化平凡基线，非可选框架。
- **当前架构 RamsNet(当前架构,多任务)（共享 GRU 多任务）**：3.643±0.044，是所有学习框架中最低，比次优（DLinear，5.519）低 -1.876（-51.5%）。
- **GRU 单任务代理**：5.890±0.138，比多任务版差 2.246——多任务/分位数损失贡献显著。
- **结论：GRU 当前架构是最优框架，无更优替换。** 注意力（Transformer/TFT/PatchTST）、线性深度（DLinear/TSMixer）、传统 ML（XGB/LGB）全部显著更差（5.5-6.3 vs 3.6）。
  - 唯一有效的「提升」不是换框架，而是数据量/评估协议（见运行细节：固定切分下持久化占优是方差不匹配假象）。

## 诚实记录

- **过拟合观测**（val/train 归一化 RMSE 比 > 1.5，训练段 RMSE 已显著低于验证段）：
  - `XGBoost`：train 0.169 / val 0.398（比 2.35×）——模型记住训练段（高波动含藻华），泛化到低波动测试段困难。
  - `LightGBM`：train 0.153 / val 0.392（比 2.56×）——模型记住训练段（高波动含藻华），泛化到低波动测试段困难。
  - `TSMixer`：train 0.287 / val 0.445（比 1.55×）——模型记住训练段（高波动含藻华），泛化到低波动测试段困难。
  - `TFT(简版)`：train 0.266 / val 0.488（比 1.83×）——模型记住训练段（高波动含藻华），泛化到低波动测试段困难。
- 持久化 train_rmse_norm=0.63 偏高是**协议现象**：训练段（2021-2024）含藻华高波动（std≈13.9），而测试段（2025）低波动（std≈3.1），持久化在平稳段天然低误差。勿把它解读为模型能力。
- TFT：未安装 pytorch_forecasting（PyPI 可达但依赖 Lightning 较重，且本任务不需要完整库），采用同架构简版（GRN + LSTM + 多头注意力 + 静态 depth 协变量 + 分位数头），核心机制一致。

## 运行细节

- 评估口径：测试集 RMSE（还原原始浓度尺度），3 seed 均值±std。
- 已知协议局限（LOG.md / t2_public_baseline.md）：固定 70/15/15 时序切分下，训练段（2021-2024，含藻华，std≈13.9）与测试段（2025，低波动，std≈3.1）方差严重不匹配，会导致「模型 RMSE 高于持久化」的失真现象。RMSE 只反映固定切分下的相对排序，跨模型横向对比仍公平（同一数据/切分/评估）。
- 参考基线 RamsNet(当前架构,多任务) 即生产架构（共享 GRU + M1/M2/M4 多任务 + 分位数损失，与 `rams/training/trainer.py` 同构）；GRU(当前架构,单任务) 为去掉多任务/分位数后的能力下限。已归档完整多任务版本 M1 RMSE≈3.44-3.64（t1_integration）。
- 模型数：12；覆盖 3 梯队（传统 ML / 线性深度 / 注意力）。
